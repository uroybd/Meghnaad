# 0006: The terminal app's own task info

- **Status:** draft <!-- draft | ready | in progress | done | dropped -->
- **Created:** 2026-11-16
- **Layer:** 2 (UI), with one helper from layer 1 (time sessions)
- **Front ends:** terminal. The web and Android already have their own panel (`TaskInfo.svelte`, `TaskInfo.kt`); they
  change only if they move to the shared sessions helper.
- **Supersedes / related:** 0001 (field transformation): its criterion for the terminal's info view is met here, as
  that view is `task info` verbatim today.

## Why

The terminal app's info view (`Mode::Info`, drawn in `crates/tui/src/ui.rs`) prints `task info` as it is. It can't
show what the web and the phone show in theirs: transformed descriptions and links (0001), the time log (sessions from
`journal.time`), recurrence instances, blockers, and the properties no UDA defines. It is also one long page, so
getting to the annotations or the time log of a busy task means scrolling past everything else.

## What

1. `Enter` on a task (`tasks.info`) opens the app's own info view in place of `task info`, built from what the web's
   `TaskInfo` shows, in sections:
   - **Details:** description (transformed and drawn as in report rows), status, project, priority, tags, dates,
     active time, depends and blocking, UDAs, virtual tags.
   - **Recurrence:** the template or parent, and the instances.
   - **Time log:** each session (start, end or running, length) and the total.
   - **Annotations:** each, transformed and drawn as Markdown.
   - **History:** see Open questions.
   - **Unknown properties:** the ones no UDA defines.
   An empty section is left out.
2. The sections have a title line each and can be jumped to: a key for the next and the previous section, and a key
   for each section by name. A line at the bottom lists the sections and their keys.
3. A key opens the plain `task info` as it is now, for anything the view doesn't show.

## Not doing

- Editing from the info view (the task form and task commands do that).
- Changing the web or Android panels, beyond using the shared sessions helper if that is chosen.
- A command of our own for the screen: the data is `export`, as AGENTS.md says.

## Design

Proposal, for a yes before building:

- **Data:** `<uuid> export` through `task.rs`, as the rest of the app reads tasks; instances by `parent:<uuid>
  export`, blockers by the `depends` uuids. Nothing new in the engine for these.
- **Time log:** pairing `journal.time`'s start and stop annotations into sessions is Taskwarrior's knowledge
  (`Facts::sessions`, `crates/tc-core/src/model.rs`). It goes behind a `tc_core::helpers` function taking a task's
  JSON and the two marker texts, so the terminal app doesn't copy it. The engine keeps calling `Facts::sessions` as it
  does.
- **Drawing:** a new `crates/tui/src/app/info.rs` builds the sections as lines (reusing `md.rs` for transformed text
  and links, and the report's date format); `ui.rs` draws them in a scrolling pane with the section titles, and the
  jump keys move the scroll to a title.
- **Keys:** the app's own moves, as everywhere (vim's): `j` `k` a line, `[` `]` the section before and the next
  (`move.sectionPrev`, `move.sectionNext`, which the info view already answers), `Ctrl+D` `Ctrl+U` half a page,
  `g` `G` the top and the end. New in an `info` context of `web/public/keymaps/default.json`: one key per section
  (`d` details, `r` recurrence, `t` time log, `a` annotations, `h` history, `u` unknown) and `info.raw` (`i`) for plain
  `task info`. `?` lists them. The copy for the phone is regenerated by `scripts/gen-lucide.mjs`.

## Acceptance criteria

- [ ] `Enter` on a task opens the sections above, each left out when empty, with transformed descriptions, annotations
      and string UDAs, and links that open.
- [ ] The time log lists the same sessions and total as the web panel for the same task, from the shared helper.
- [ ] Next, previous and the per-section keys move to that section's title; the bottom line names them; `?` lists them.
- [ ] The plain `task info` is still one key away.
- [ ] Tests: the helper in `tc-core`; the TUI's sections built from an `export` (and against the real `task` 3.5.0 on
      a scratch `TASKRC`, skipped where it is missing); the jump keys.
- [ ] Docs: `docs/terminal.md` (the info view and its keys).

## Open questions

- History: the web gets it from `_history`, which only our engine has. The real `task` shows a task's changes only
  inside `task info`. Keep that part of `task info` as a section (parsing its output), leave history to the plain
  `task info` key, or leave it out?
- Should the web and Android move to the shared sessions helper too, or keep reading `sessions` from `_rows`?
- Tabs instead of one long page (suggested 2026-11-16): the sections as tabs along the top, one shown at a time, `[`
  `]` going to the tab before and the next, as the Settings page already shows one section at a time. Easier to take
  in, and a busy section scrolls on its own; the cost is not seeing two sections at once. If chosen, **What** 2, the
  drawing and the criterion on the keys change to match.
