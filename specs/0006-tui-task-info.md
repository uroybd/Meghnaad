# 0006: The terminal app's own task info

- **Status:** in progress <!-- draft | ready | in progress | done | dropped -->
- **Created:** 2026-11-16
- **Layer:** 2 (UI), with one helper from layer 1 (time sessions)
- **Front ends:** terminal; the web and Android only move their time log to the shared sessions helper (their panels,
  `TaskInfo.svelte` and `TaskInfo.kt`, are otherwise unchanged).
- **Supersedes / related:** 0001 (field transformation): its criterion for the terminal's info view is met here, as
  that view is `task info` verbatim today.

## Why

The terminal app's info view (`Mode::Info`, drawn in `crates/tui/src/ui.rs`) prints `task info` as it is. It can't
show what the web and the phone show in theirs: transformed descriptions and links (0001), the time log (sessions from
`journal.time`), recurrence instances, blockers, and the properties no UDA defines. It is also one long page, so
getting to the annotations or the time log of a busy task means scrolling past everything else.

## What

1. `Enter` on a task (`tasks.info`) opens the app's own info view in place of `task info`, built from what the web's
   `TaskInfo` shows, in tabs: **Details**, **Recurrence**, **Time log**, **Annotations**, **Unknown properties**. A tab
   with nothing in it is left out. A task's history isn't shown; it stays in the plain `task info`.
   - **Details:** description (transformed and drawn as in report rows), status, project, priority, tags, dates,
     active time, depends and blocking, UDAs, virtual tags.
   - **Recurrence:** the template or parent, and the instances.
   - **Time log:** each session (start, end or running, length) and the total.
   - **Annotations:** each, transformed and drawn as Markdown.
   - **Unknown properties:** the ones no UDA defines.
2. The tabs run along the top, one shown at a time, as the Settings page shows its sections. `[` `]` go to the tab
   before and the next; a key for each goes straight to it. In a tab, the app's usual moves scroll it.
3. A key opens the plain `task info` as it is now, for anything the view doesn't show.

## Not doing

- Editing from the info view (the task form and task commands do that).
- Changing the web or Android panels, beyond drawing their time log from the shared sessions helper.
- A command of our own for the screen: the data is `export`, as AGENTS.md says.

## Design

Agreed 2026-11-16.

- **Data:** `<uuid> export` through `task.rs`, as the rest of the app reads tasks; instances by `parent:<uuid>
  export`, blockers by the `depends` uuids. Nothing new in the engine for these.
- **Time log everywhere from one helper** (decided 2026-11-16): pairing `journal.time`'s start and stop annotations
  into sessions is Taskwarrior's knowledge (`Facts::sessions`, `crates/tc-core/src/model.rs`). It goes behind a
  `tc_core::helpers` function taking a task's JSON (and the settings, for the marker texts), and every front end draws its time log from it: the terminal from the task's `export`, the web
  through `web/src/engine/helpers.ts` (page thread, as the other helpers) and Android through
  `crates/android/src/helpers.rs`. `_rows` keeps its `sessions` field (the app-only commands stay as they are), but no
  screen reads it for the time log.
- **No history** (decided 2026-11-16): the view has no History tab; a task's changes stay in the plain `task info`.
- **Tabs** (decided 2026-11-16): a new `crates/tui/src/app/info.rs` builds each section's lines (reusing `md.rs` for
  transformed text and links, and the report's date format); `ui.rs` draws the tabs along the top of the pane (the
  shown one in the accent, an empty one left out) and the shown tab's lines under them, scrolled on their own, as the
  Settings page shows one section at a time. Each tab keeps its scroll while the view is open.
- **Keys:** the app's own moves, as everywhere (vim's): `[` `]` the tab before and the next (`move.sectionPrev`,
  `move.sectionNext`), and in the tab `j` `k` a line, `Ctrl+D` `Ctrl+U` half a page, `g` `G` the top and the end. New
  in an `info` context of `web/public/keymaps/default.json`: one key per tab (`d` details, `r` recurrence, `t` time
  log, `a` annotations, `u` unknown) and `info.raw` (`i`) for plain `task info`. `?` lists them. The copy for the phone
  is regenerated by `scripts/gen-lucide.mjs`.

## Implementation notes

Filled in while building: what was done, where, anything that differed from the design and why, sizes measured, and
what is left. Dated entries, newest last.

- 2026-11-16: What 1–2 and the first three criteria changed to the decisions (tabs, no history, the time log from the
  shared helper everywhere), confirmed by the person. Set to ready, then in progress; building starts.
- 2026-11-16: Built.
  - **Engine:** `tc_core::helpers::time_log` (`TimeTask`, `Markers`, `TimeLog`), `Facts::sessions` behind it; the
    helper name `time_log`.
  - **Web:** `timeLog` in `web/src/lib/journal.ts`; `TaskInfo.svelte` draws the sessions and the total from it rather
    than from `_rows`' `sessions`.
  - **Android:** `timeLog` and `TimeLog` in `Journal.kt`; `TaskInfo.kt` draws from it. `DetailScreen.kt` no longer
    grows the running session between fetches, as the log is read as of now each time it is drawn.
  - **Terminal:** `crates/tui/src/info.rs` builds the tabs from `export`. `app/taskinfo.rs` opens the view (`Enter`):
    the task, its template, its instances (`parent:<uuid>`), what it depends on and what waits on it
    (`depends.has:<uuid>`), all with `rc.context=`. It also has the view's keys. `Mode::TaskInfo` is drawn by
    `task_info` in `ui.rs`: the tab line, then the shown tab wrapped and scrolled, each tab keeping its own place.
    `Mode::Info` stays for `?` and for `i`.
  - **Keys:** an `info` context (`info`, `move`) in `default.json` with `info.details` `d`, `info.recurrence` `r`,
    `info.timeLog` `t`, `info.annotations` `a`, `info.unknown` `u`, `info.raw` `i`. `[` `]` are the shared
    `move.sectionPrev` and `move.sectionNext`. The phone's copy is updated.
  - **Departures:**
    - Details shows no virtual tags: `export` doesn't carry them, and no helper works them out from a task's JSON.
    - "Active" is how long since `start`, not the engine's `active_seconds`; the Time log tab has the tracked total.
  - **Tests:** `time_log` in `helpers.rs`; web `TaskInfo.test.ts` (the time log); Kotlin `JournalTest`; the TUI's
    `info.rs` (the tabs, a transformed description, a template's instances, going round); and `tests/task_info.rs`
    against the real `task` 3.5.0 (tabs, Blocking, the journal's session, the keys, `i`, a template's instances).
    Seen on a screen in a private tmux with scratch data.
  - **Checks:** all pass. `cargo test` 1,058; Lua hooks 15; web 819; svelte-check; scripts 34; both wasm checks;
    Kotlin tests and `assembleDebug`; lint; `mdbook build`.
  - **Size:** engine 855,985 → 858,785 bytes gzipped (+2.8 KB). The Worker is untouched.
  - **Left:** the first criterion. Nobody has clicked a link in the view yet; it uses the same OSC 8 links as report
